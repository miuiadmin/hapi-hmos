# 打包流程（dist.sh）

## 1 个包的来源

`下载服务器/scripts/dist.sh` 只产 1 个安装包到 `output/dist/<版本>_<时间戳>/`：

| # | 产物 | 命令 | 包名 | 签名 |
|---|------|------|------|------|
| 1 | `hapi-X-88-release.app` | `tools/pack.sh`（默认固定后缀 88 + release） | com.twsxtd.hapi88 | ❌ 未签名（侧载包） |

> **为什么只 1 个**：OTA 只推 88 共存包（正式版走 AGC 应用市场；debug 按需 `build.sh app-debug` 手打）。1 次编译，最快路径。

## AboutPage 时间戳的字节级恢复（hapi 不适用）

berry 的 `pack.sh` 步骤 0 会 `sed -i ''` 改 `entry/.../AboutPage.ets` 的 `BUILD_DATE_MARKER` 时间戳且**不恢复**，berry 的 dist.sh 用字节级备份 + trap 恢复处理（比 `git checkout` 安全，不影响用户对该文件的并行改动）。

**hapi 无 AboutPage.ets，dist.sh 移植时已整段删除备份/恢复逻辑**（无 `mktemp` / `trap cleanup` / `ABOUT_BAK`），无此步骤。本节保留作 berry 历史对照。

## 产物命名规则

```
hapi-<versionName>-88-release.app
```
- `88-release`：变包名 com.twsxtd.hapi88，release（⭐OTA 升级源，与正式版互不冲突）

## manifest.json（OTA 元数据）

dist.sh 写一份元数据 JSON（页面不显示，供 nodebook `/hapi-ota/update.json` 实时读 → 拼 OTA UpdateInfo）：
```json
{
  "version": "0.1.0",
  "versionCode": 1000000,
  "bundleName": "com.twsxtd.hapi88",
  "buildTime": "2026-08-03T12:30:00",
  "date": "2026-08-03",
  "changelog": [],
  "files": [
    { "name": "hapi-0.1.0-88-release.app", "type": "88共存 release", "size": 29999999, "md5": "<小写32位>" }
  ]
}
```

字段来源：
- `version` / `versionCode`：sed 从 `AppScope/app.json5` 提取（versionCode 用 `sed -E`，⚠️BSD sed BRE 下 `\+` 是字面加号会提取空）
- `bundleName`：固定 `com.twsxtd.hapi88`（pack.sh 默认 88 后缀）。**客户端 `SelfUpdateManager` 校验「下载包 bundleName === 当前包 bundleName」防 88 包装到非 88 包**
- `changelog`：hapi **无 changelog.json，固定为 `[]`**（供 OTA 弹窗展示更新日志；将来加 changelog.json 再接 jq 抽取）
- `files[].md5`：macOS `md5 -q` / Linux `md5sum`（小写，与 APP 端 `@ohos.file.hash` 返回大写后 `toLowerCase` 对齐）
- `files[].size`：`stat -f%z`

服务端 `listFiles()` 排除 `manifest.json` 与 `uploaded.json`，二者都不显示在下载列表。

## HTTP 上传后的两个副产物

`sync-server.sh` 上传成功后服务端会写两个运行时文件（页面功能依赖）：

- **`archive/<日期>/<版本>/uploaded.json`**：`{"uploadedAt":"2026-08-03 15:14:12"}`（北京时间精确到秒），页面顶部「上传于」读它。回退链：uploaded.json → manifest.buildTime → 日期目录名。
- **`files/stats/downloads.json`**（⚠️ 在 `archive` **同级**的 `stats/` 下，**不在**归档目录里）：`{"<日期>/<版本>/<文件名>": <下载次数>}`，每点一次下载按钮 +1。**必须放在 archive 外**，否则重新发布同版本会清零计数。

## ⚠️ 发版时序约束：nodebook 必须先于新客户端部署

新客户端（`SelfUpdateManager.parseUpdateInfo`）要求 `/hapi-ota/update.json` **必须带 bundleName**（非空字符串），否则返回 null（视为无更新）。

- **正确顺序**：**先部署 nodebook**（含 bundleName 的 hapi OTA 路由）**→ 再发新客户端**。
- 若新客户端先发、nodebook 未部署 → 旧 nodebook 的 `/hapi-ota/update.json` 不含 bundleName → 新客户端 OTA 失效（拉到 JSON 但解析失败→无更新）。
- 向前兼容：新 nodebook 的 update.json 多了 bundleName 字段，旧客户端忽略多余字段，不受影响。所以只需保证「nodebook 先部署」。

## 耗时

约 1 次编译（pack.sh 默认 88 后缀打 release .app，单次 clean+编译）。整体约 2 分钟。

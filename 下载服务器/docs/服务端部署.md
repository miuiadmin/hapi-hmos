# 服务端部署（多 App OTA 托管改造）

> 对应 nodebook-rs 的「参数化多 App OTA」改造（berry 模块驱动 `apps` 注册表）。本次部署只新增 **4 个 `.env` 键** + 重建二进制 + 建归档目录，**berry 零回归**（`/berry` + `/ota` 行为不变）。

## 改造后路由总览

| 路由 | 鉴权 | 数据源 | 说明 |
|------|------|--------|------|
| `/berry/*` | `?t=BERRY_TOKEN` | `FILES_ROOT` | berry 浏览/上传（不变） |
| `/berry-ota/*` | 免 token | `FILES_ROOT` | berry OTA（新增字面路由，与别名同源） |
| `/ota/*` | 免 token | `FILES_ROOT` | **berry OTA 别名**（客户端硬编码 `/ota/update.json`，零回归） |
| `/hapi/*` | `?t=HAPI_TOKEN` | `HAPI_FILES_ROOT` | hapi 浏览/上传（**本次新增**） |
| `/hapi-ota/*` | 免 token | `HAPI_FILES_ROOT` | hapi OTA（**本次新增**，APP 内置地址） |

berry / hapi 计数按各自 `files_root` 隔离（各自一份 `downloads.json`，互不污染）。

## 部署步骤

### 步骤 0 · 生成 hapi token（本地任意机器）

```bash
openssl rand -hex 24        # 例如 3f9a...（48 位 hex），记下来,下一步要写进两个地方
```

> 这个 token 同时是：① 服务端 `HAPI_TOKEN`；② hapi-hmos `下载服务器/scripts/config.sh` 的 `TOKEN`。两边必须一致。

### 步骤 1 · 改服务器 `.env`（加 4 个键）

服务器 `.env` 在 `/root/nodebook-rs/.env`（systemd `WorkingDirectory=/root/nodebook-rs`，dotenvy 自动读）。追加：

```bash
ssh root@47.130.2.49

# 在服务器上:
cd /root/nodebook-rs
cp .env .env.bak.$(date +%s)          # 先备份,出问题秒回滚

cat >> .env <<'EOF'

# ===== hapi 下载站(多 App OTA 托管;2026-08-03 加)=====
HAPI_TOKEN=步骤0生成的token
HAPI_FILES_ROOT=/opt/hapi-dist/files/archive
HAPI_KEEP_VERSIONS=3
HAPI_HOST=berry.flyme.chat:8443
EOF

# 校验:四个键都已写入、值非空
grep -E '^HAPI_' .env
```

| 键 | 必填 | 默认 | 说明 |
|----|------|------|------|
| `HAPI_TOKEN` | ✅ | — | 空 = hapi 路由不挂载（=本次改造前的状态） |
| `HAPI_FILES_ROOT` | 否 | `/opt/hapi-dist/files/archive` | hapi 归档根；**须与 berry 的 `FILES_ROOT` 不同父目录**（否则 `downloads.json` 磁盘文件撞车，计数串） |
| `HAPI_KEEP_VERSIONS` | 否 | `3` | 上传后保留最新 N 版，0=不清理 |
| `HAPI_HOST` | 否 | `berry.flyme.chat:8443` | OTA `url` 字段 + TG 下载页用的对外域名 |

> ⚠️ `HAPI_TOKEN` 改完**先别重启**——二进制还没换，旧二进制不认这些键（只是 dotenvy 多读几个变量，不报错，但 hapi 路由也不会生效）。下一步换完二进制再重启。

### 步骤 2 · 建归档目录（服务器）

```bash
# 仍在服务器上
mkdir -p /opt/hapi-dist/files/archive
ls -ld /opt/hapi-dist/files/archive     # 确认存在
exit                                    # 退出 ssh,回本地
```

### 步骤 3 · 本地交叉编译（Mac）

```bash
cd /Users/murongcheng/Documents/code/test/nodebook-rs

# 编前关 Safari/IDE 腾内存(ship profile LTO 单进程 4-6G,-j1 串行)
./cross/build.sh
# 产物:~/.cargo-target/x86_64-unknown-linux-musl/ship/nodebook(静态 musl,跨机器直跑)
```

> 首次约 5-10 分钟。脚本末尾会打印产物路径 + scp 命令模板。

### 步骤 4 · 上线二进制 + 重启

```bash
BIN="$HOME/.cargo-target/x86_64-unknown-linux-musl/ship/nodebook"

# 先备份在跑的二进制(回滚用)
ssh root@47.130.2.49 "cp /usr/local/bin/nodebook-rs /usr/local/bin/nodebook-rs.bak.$(date +%s)"

# scp 新二进制 → 原子替换 → 重启
scp "$BIN" root@47.130.2.49:/usr/local/bin/nodebook-rs.new
ssh root@47.130.2.49 'mv -f /usr/local/bin/nodebook-rs.new /usr/local/bin/nodebook-rs && chmod +x /usr/local/bin/nodebook-rs && systemctl restart nodebook-rs'

# 确认起来(状态 active + 近日志无 panic)
ssh root@47.130.2.49 'systemctl is-active nodebook-rs && journalctl -u nodebook-rs -n 20 --no-pager | tail -15'
```

看到 `listening [HTTP/1.1] on ...` 即起服务成功。

### 步骤 5 · 冒烟测试（本地 curl）

```bash
B=https://berry.flyme.chat:8443
HTOK=步骤0的token        # = HAPI_TOKEN

# ★ berry 零回归(必须和改造前一模一样)
curl -s -o /dev/null -w "berry 无token(401): %{http_code}\n"          "$B/berry"
curl -s -o /dev/null -w "berry 有token(200): %{http_code}\n"          "$B/berry?t=$BTOK"   # BTOK=旧 BERRY_TOKEN
curl -s "$B/ota/update.json" | python3 -c "import sys,json;d=json.load(sys.stdin);print('ota url =',d['url'])"
# 期望 url = https://berry.flyme.chat:8443/ota/latest  ← 别名路径不变

# ★ hapi 新增
curl -s -o /dev/null -w "hapi 无token(401): %{http_code}\n"           "$B/hapi"
curl -s -o /dev/null -w "hapi 有token(200): %{http_code}\n"           "$B/hapi?t=$HTOK"
curl -s -o /dev/null -w "hapi 用berry token(须401): %{http_code}\n"   "$B/hapi?t=$BTOK"
curl -s "$B/hapi-ota/update.json" | head -c 120; echo
# 空清单时返回 404 "no release" 是正常的(还没上传包);路由存在即 ✅
```

判定：berry 两条 401/200 + `/ota/update.json` 的 `url` 仍是 `/ota/latest`；hapi 401/200/401 隔离正常 → **部署成功**。

### 步骤 6 · 发版上架 hapi 0.0.1

```bash
cd /Users/murongcheng/Documents/code/hapi-hmos

$EDITOR 下载服务器/scripts/config.sh      # 填 TOKEN=<步骤0的token>;PUBLIC_URL=https://berry.flyme.chat:8443

```

## 回滚（出问题时）

二进制层回滚（最快，不动 .env）：

```bash
ssh root@47.130.2.49 'cd /usr/local/bin && L=$(ls -t nodebook-rs.bak.* | head -1) && cp -f "$L" nodebook-rs && chmod +x nodebook-rs && systemctl restart nodebook-rs'
```

`.env` 回滚（恢复改造前、彻底关掉 hapi）：

```bash
ssh root@47.130.2.49 'cd /root/nodebook-rs && L=$(ls -t .env.bak.* | head -1) && cp -f "$L" .env && systemctl restart nodebook-rs'
```

回滚后 hapi 路由消失（`HAPI_TOKEN` 为空→不挂载），berry 完全不受影响。

## 备注

- **berry 计数无损**：`downloads.json` 路径与键名都没变（`stats.rs` 只多了外层 `files_root` 键，berry 子 map 原样加载）。
- **磁盘计数隔离前提**：berry 与 hapi 的 `*_FILES_ROOT` 必须**不同父目录**（生产 `/opt/berry-dist` vs `/opt/hapi-dist` 天然满足）。若把两个 app 放同一父目录下，进程内计数仍隔离，但磁盘 `downloads.json` 会撞车（后写覆盖先写）。
- nodebook-rs 本目录**非 git 仓库**（只有 `.gitignore`），无提交动作；改动直接在源码文件上，`cross/build.sh` 编译即生效。

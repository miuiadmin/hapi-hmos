# 参考项目

移植 Hapi 鸿蒙客户端时，有三类参考。**chatcube 主（业务 / UX）；berry3 主（ArkTS 语法 + 避坑文档 + 底层）；hapi 源码主（语义 / 协议）。**

## 参考优先级

| 优先级 | 项目 | 参考范围 |
|---|---|---|
| 🥇 **业务/UX** | chatcube（Cube Chat） | **布局、样式、流式对话、对话、会话管理** —— 业务 / 架构 / UX 全方位对齐 |
| 🔧 **语法/避坑/底层** | berry3（Berry Browser） | **ArkTS 语法 + 避坑文档库**（遇坑先查）+ 底层代码（系统能力） |
| 语义 | `参考源码/hapi`（官方上游） | 功能行为、Hub 交互协议、数据结构（见 [官方仓库对照.md](官方仓库对照.md)） |

> **为什么这样分**：chatcube 是 ArkTS 原生 AI 聊天客户端，与 Hapi 客户端业务同构（都是 AI 对话 + 会话管理），布局 / 样式 / 对话 / 会话以它为准；berry3 虽业务是浏览器（UI 不参考），但与 Hapi **同 ArkTS/ArkUI 技术栈**，积累了大量踩坑经验与语法范式，是 **ArkTS 避坑文档库 + 语法参考 + 底层实现**的三重来源；`参考源码/hapi` 是语义 / 协议的唯一真相源。

## chatcube（Cube Chat）—— 业务 / UX 主要参考

面向鸿蒙 6（API 23）的**原生 AI 聊天客户端**：ArkTS 原生开发（非 WebView），15+ provider，联网搜索 + MCP，MVVM 架构。与 Hapi 客户端几乎同构，是布局 / 样式 / 对话 / 会话的一手参考。

| 本地路径 | `参考源码/chatcube` |
| 当前 commit | `fd729d0` |
| 状态 | **已归档（只读快照）** |
| License | **MIT** |

### 页面 / 能力参考映射

| Hapi 要做的 | chatcube 参考 |
|---|---|
| **登录页**（填 Hub 地址 + token） | `components/onboarding/OnboardingStepProvider`、`components/provider`、`components/settings`（provider 配置范式，正好对应「填地址 + key」） |
| **会话列表页** | `pages/index/`：`IndexSessionListDataSource`（列表数据源）、`IndexSessionGroupHelper`（分组）、`IndexTabsVisibilityHelper`（标签）、`IndexSettingsSheetCoordinator`（设置面板） |
| **对话页** | `pages/chat/`：`ChatSendFlow`（发送）、`ChatStopFlow`（停止）、`ChatScrollUiFlow`（滚动）、`ChatReasoningStateHelper`（推理状态）、`ChatToolIdHelper`（工具调用）、`ChatInlineEditFlow`（内联编辑）、`ChatSelectionFlow`（选择） + `components/chat/` |
| **流式对话** | `pages/chat` 的 Flow 系列（发送 / 停止 / 滚动 / 推理 均为流式驱动）+ `services/`（SSE / 流式协议） |
| **会话管理** | `pages/index` + `state/`（会话状态）+ `viewmodels/` |

### 架构要点（可借鉴）

- **MVVM**：`viewmodels/`（视图模型）+ `state/`（含 `migrations/` 状态迁移）+ `models/`
- **provider 注册**：`services/registry/`（多服务商统一接入，类比 Hapi 接不同 Hub）
- **设计系统**：`ui/hds/`（自有 UI 设计系统）
- **联网搜索 / MCP**：`services/search/`

### berry3 避坑文档（★ 遇坑先查）

berry3 是完整鸿蒙项目，积累了大量 ArkTS/ArkUI 踩坑经验。**写 ArkTS 遇坑先翻这些文档**（hapi-hmos 用 `@ComponentV2` 严格模式，几乎都会撞上）：

| 文档 | 内容 |
|---|---|
| **`docs/ArkUI-V2严格模式避坑.md`**（最常查） | 9 条 V2 坑：`build()` 禁调 getter / 私有方法、`@Local` 镜像驱动重渲染、singleton `@ObservedV2`/`@Trace` 不触发子组件 build、`@BuilderParam` 方法引用丢绑定闪退、NavDestination 遮挡返回 frozen 脏状态、声明式重渲染延迟导致竞态… |
| `Harmony开发避坑文档.md`（根目录，3733 行） | 23+ 通用坑：`swipeAction` @Builder `this` 上下文、嵌套 `ForEach` 闭包过期、`preferences.flush` 未 await 丢数据、`@Builder` 断依赖追踪、Worker `@bundle` 路径 SIGABRT、hvigor 增量缓存 Load Page Failed、`JSON.parse` 丢 `@ObservedV2`/`@Trace`、logcat 抓不到日志… |
| `docs/DevEco-CLI使用文档.md` | `devecocli` 工具（比裸 hvigorw+hdc 强：build/run/device/log + 官方文档本地检索） |
| `docs/官方Sample参考提炼.md` / `docs/系统SymbolGlyph图标速查表.md` / `docs/加载循环诊断与防御.md` | 官方样例提炼、系统图标速查、加载循环防御 |
| berry3 `CLAUDE.md` / `AGENTS.md` | 项目约定 + logcat 扩缓冲区实时关键字采集方案 + 状态装饰器 V2/V1 对照 + 常用 tag |

> **印证**：hapi-hmos 已踩的坑 —— `build()` 禁调 getter（ArkTS 10905209）、`@Builder` 内禁 const（10905210）、对象字面量严格模式、`CustomComponent` 的 `scale`/`size` 撞 ArkUI 通用属性 —— berry3 的 V2 避坑文档第 1 条就记着。**先查文档能少走弯路。**

### 什么时候用 berry3

- **ArkTS / ArkUI 遇坑**（build/getter/ForEach/@Trace/@Local/JSON.parse/状态装饰器/签名/hvigor 增量/日志抓取…）→ **先查 berry3 避坑文档**（尤其 `docs/ArkUI-V2严格模式避坑.md`）
- 某**系统能力**（通知、后台任务、文件、网络底层、窗口管理…）或 **API 实证**（如 `AlertDialog` button 用 `fontColor` 非 `color`、vibrator 走 `@kit.SensorServiceKit`）在 chatcube 里找不到 → 翻 berry3 代码
- ArkTS **语法范式**不确定（对象字面量、`Record` 构造、`@Builder` 参数传递…）→ 查 berry3 写法

> 规则：**布局 / 样式 / 对话 / 会话以 chatcube 为准**（不要参考 berry3 的浏览器 UI）；**ArkTS 遇坑 / 底层 / 语法以 berry3 为准**。License：berry3 未明确 → **避坑文档知识可参考（写自己的实现），代码不搬**。

## 鸿蒙官方文档检索（skill，本项目自带）

查询鸿蒙官方文档的两个 retriever skill，自包含、纯 Python 标准库、已复制到 `.claude/skills/`：

| skill | 用途 |
|---|---|
| `hmos-arkts-knowledge-retriever` | 检索 **ArkTS 语言指南**（语法、库、并发、运行时） |
| `hmos-arkui-knowledge-retriever` | 检索 **ArkUI 知识库**（组件、API、状态管理 V1/V2、错误码） |

由 AI 助手按需触发。脚本入口：`scripts/search_docs.py`（arkts）、`scripts/run.py`（arkui），需 Python 3。

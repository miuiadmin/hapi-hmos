# 参考项目

移植 Hapi 鸿蒙客户端时，有三类**一线**参考 + 一个**二线**参考。**chatcube 主（业务 / UX / UI 样式）；berry3 主（ArkTS 语法 + 避坑文档 + 底层）；hapi 源码主（语义 / 协议）**；**paseo 二线（agent 编排业务范式 + daemon-client 架构设计，RN + TS 技术栈，不参考 UI 样式 / ArkTS 语法）**。

## 参考优先级

| 优先级 | 项目 | 参考范围 |
|---|---|---|
| 🥇 **业务 / UX / UI 样式** | chatcube（Cube Chat） | **UI 样式（颜色 / 主题 / 字体 / 圆角 / 间距 / 动效）**、布局、流式对话、对话、会话管理 —— 业务 / 架构 / UX 全方位对齐 |
| 🔧 **语法 / 避坑 / 底层** | berry3（Berry Browser） | **ArkTS 语法 + 避坑文档库**（遇坑先查）+ 底层代码（系统能力） |
| 语义 | `参考源码/hapi-v0.25.4`（官方上游，当前主参考 v0.25.4） | 功能行为、Hub 交互协议、数据结构（见 [官方仓库对照.md](官方仓库对照.md)） |
| 🥈 **二线** | paseo（Paseo） | chatcube 未覆盖的 **agent 编排业务范式**（多 agent 并行 / worktree / 工具调用编排 / 跨设备控制）+ **daemon-client 架构设计**（WebSocket RPC / 协议版本兼容 / 状态机 / 终端性能）。RN + TS，**不参考 UI 样式与 ArkTS 语法** |

> **为什么这样分**：chatcube 是 ArkTS 原生 AI 聊天客户端，与 Hapi 客户端业务同构（都是 AI 对话 + 会话管理），布局 / 样式 / 对话 / 会话以它为准；berry3 虽业务是浏览器（UI 不参考），但与 Hapi **同 ArkTS/ArkUI 技术栈**，积累了大量踩坑经验与语法范式，是 **ArkTS 避坑文档库 + 语法参考 + 底层实现**的三重来源；`参考源码/hapi-v0.25.4` 是语义 / 协议的唯一真相源（旧版 `hapi-v0.18.4` 仅作历史对比）。

> 🔒 **UI 样式铁律**：Hapi 的所有 UI 视觉样式 —— **颜色、主题（明 / 暗）、字体、圆角、间距、阴影、动效、组件视觉** —— **一律以 chatcube 为准**。任何样式拿不准，**先翻 chatcube 对应实现**，不要自行设计、不要参考 berry3 的浏览器 UI。样式 = 品牌一致性，这是硬约束（具体文件见下文 chatcube「UI 样式参考」表）。

### 架构要点（可借鉴）

- **MVVM**：`viewmodels/`（`ChatViewModel` / `ChatSessionStore` / `SettingsManager` 等 7 个）+ `state/`（含 `migrations/` 状态迁移）+ `models/`
- **provider 注册**：`services/registry/`（`ProviderProfileRegistry` / `ModelAbilityRegistry` / `CompatibilityResolver` —— 多服务商统一接入，类比 Hapi 接不同 Hub）
- **联网搜索**（≠ MCP）：`services/search/`（搜索引擎注册表 `SearchEngineRegistry`）+ `services/WebSearchService.ets`
- **MCP**（≠ 联网搜索）：`services/McpService.ets` + `models/McpModels.ets`（JSON-RPC over HTTP）
- **样式 / 主题系统**：`models/ThemeColors.ets`（颜色 token + 预设主题：DEFAULT / CLAUDE / CHATGPT / VIOLET / MINT / NOTION）+ `config/ThemeDefaults.ets` + `services/ThemeService.ets` + `resources/{base,dark}/element/color.json` + 多套色主题。**UI 样式的一手来源，见下表。**

### berry3 避坑文档（★ 遇坑先查）

berry3 是完整鸿蒙项目，积累了大量 ArkTS/ArkUI 踩坑经验。**写 ArkTS 遇坑先翻这些文档**（hapi-hmos 用 `@ComponentV2` 严格模式，几乎都会撞上）：

| 文档 | 内容 |
|---|---|
| **`docs/ArkUI-V2严格模式避坑.md`**（最常查，9 条） | 9 条 V2 坑：`build()` 禁调 getter / 私有方法、`Tabs.barHeight` 须方法链、`@Local` 镜像驱动重渲染、声明式重渲染延迟致竞态、控制器须为唯一真相源、singleton `@ObservedV2`/`@Trace` 不触发子组件 build、`@BuilderParam` 方法引用丢绑定闪退、NavDestination 遮挡返回 frozen 脏状态… |
| `Harmony开发避坑文档.md`（根目录，3733 行，**56 条**） | 56 条通用坑（含若干多子坑条目）：`swipeAction` @Builder `this` 上下文、嵌套 `ForEach` 闭包过期、`preferences.flush` 未 await 丢数据、`@Builder` 断依赖追踪、Worker `@bundle` 路径 SIGABRT、hvigor 增量缓存 Load Page Failed、`JSON.parse` 丢 `@ObservedV2`/`@Trace`、logcat 抓不到日志… |
| `docs/DevEco-CLI使用文档.md` | `devecocli` 工具（比裸 hvigorw+hdc 强：build/run/device/log + 官方文档本地检索） |
| `docs/官方Sample参考提炼.md` / `docs/系统SymbolGlyph图标速查表.md` / `docs/加载循环诊断与防御.md` | 官方样例提炼、系统图标速查、加载循环防御 |
| `docs/HDS沉浸光感文档.md` | HarmonyOS Design System 材质 / 沉浸 API（背景模糊、材质分层） |
| `docs/列表分组与入口卡设计规范.md` / `docs/卡片设计规范.md` | ArkUI 列表分组 / 卡片视觉规范（通用，hapi 列表 / 卡片可借鉴） |
| berry3 `CLAUDE.md` / `AGENTS.md` | 项目约定 + logcat 扩缓冲区实时关键字采集 + 状态装饰器 V2/V1 对照 + 常用 tag |

> **印证**：hapi-hmos 已踩的坑 —— `build()` 禁调 getter（ArkTS 10905209）、`@Builder` 内禁 const（10905210）、对象字面量严格模式、`CustomComponent` 的 `scale`/`size` 撞 ArkUI 通用属性 —— berry3 的 V2 避坑文档第 1 条就记着。**先查文档能少走弯路。**

### 什么时候用 berry3

- **ArkTS / ArkUI 遇坑**（build/getter/ForEach/@Trace/@Local/JSON.parse/状态装饰器/签名/hvigor 增量/日志抓取…）→ **先查 berry3 避坑文档**（尤其 `docs/ArkUI-V2严格模式避坑.md`）
- 某**系统能力**（通知、后台任务、文件、网络底层、窗口管理…）或 **API 实证**（如 `AlertDialog` button 用 `fontColor` 非 `color`、vibrator 走 `@kit.SensorServiceKit`）在 chatcube 里找不到 → 翻 berry3 代码
- ArkTS **语法范式**不确定（对象字面量、`Record` 构造、`@Builder` 参数传递…）→ 查 berry3 写法

> 规则：**布局 / 样式 / 对话 / 会话以 chatcube 为准**（不要参考 berry3 的浏览器 UI）；**ArkTS 遇坑 / 底层 / 语法以 berry3 为准**。License：berry3 未明确 → **避坑文档知识可参考（写自己的实现），代码不搬**。

## paseo（Paseo）—— 业务 / UX 范式 + 协议 / 架构设计二线参考

开源（**AGPL-3.0**，与 hapi-hmos 同 license）的跨平台 **AI coding agent 控制器**：本地跑 daemon 编排 Claude Code / Codex / Copilot / OpenCode / Pi 等 agent，从 iOS / Android / 桌面 / web / CLI 远程监控控制。**与 Hapi 业务高度同构**（都是「移动端控制本地 AI coding agent」），是 chatcube（通用 AI 聊天）没覆盖的「agent 编排 / 控制」业务范式的补充来源。

但 paseo 是 **React Native（Expo）+ TypeScript**，**不是鸿蒙原生**：**不参考它的 UI 样式**（仍只看 chatcube）、**不参考 ArkTS 语法**（仍看 berry3）。只取「做什么 / 怎么设计」层面的范式与架构思想。

### 参考映射（design / 范式层面，非代码搬运）

> paseo 路径均在 `参考源码/paseo/` 下。技术栈不同，**只借鉴设计 / 范式 / 协议思想，不搬代码**。

| Hapi 关注点 | paseo 参考 |
|---|---|
| **agent / 会话生命周期** | `docs/agent-lifecycle.md`（agent 状态、parent / child、archive、tabs vs archive、subagents track）—— Hapi 走 Hub 管 CLI，但生命周期 / 子 agent / 归档语义可借鉴 |
| **协议设计（客户端 ↔ daemon/hub）** | `docs/rpc-namespacing.md`（dotted namespace + `.request` / `.response`）、`docs/protocol-compatibility.md`（版本兼容、能力门控 `COMPAT` tag）、`docs/protocol-validation.md`（zod-aot 校验）—— Hapi 走 SSE + REST，但「协议不破坏向后兼容、能力门控、校验」思想相通 |

| **终端页性能** | `docs/terminal-performance.md`（终端延迟管线、coalescing / backpressure）—— Hapi 有终端页，性能范式可借鉴 |
| **移动端交互范式** | `docs/mobile-panels.md`、`docs/floating-panels.md`、`docs/menus.md`（紧凑面板、手势、popover vs sheet）—— **设计范式参考，ArkUI 实现仍看 chatcube** |
| **设计系统组织** | `docs/design.md`（tokens / buttons / hierarchy / density / alignment rails）—— docs 组织参照；**取值仍以 chatcube 为准** |

### 什么时候用 paseo

- chatcube（通用 AI 聊天）**没覆盖**的「agent 编排 / 多 agent 并行 / worktree / 工具调用编排 / 跨设备控制」业务范式 → 看 paseo 怎么设计
- **协议 / 架构设计**拿不准（客户端 ↔ Hub 的版本兼容、能力门控、RPC 命名、状态机、终端性能）→ 看 paseo 的 `docs/`

> 边界：**UI 样式 → chatcube；ArkTS 语法 / 避坑 → berry3；Hub 协议语义 → hapi 源码**。paseo 只补「业务范式 + 架构设计」这道缝，且是设计层面、非代码搬运。License 同为 AGPL-3.0，设计 / 范式可自由借鉴。
